# 第一关：一键部署、战斗与胜利结算

入口是项目根目录 `Play-Stage1.cmd`。双击后自动配置 20 单位军表、部署、开始战斗、连续作战、接受最后的投降确认，并保留胜利窗口。默认 200% 速度，关闭完整战斗演出，保留简化显示。

```powershell
.\Play-Stage1.cmd
.\Play-Stage1.cmd --speed 100
.\Play-Stage1.cmd --fast --speed 400
```

`--fast` 复用部署完成的 `states/stage1_v2_deployed.State`；不加则重新走部署。已有本项目模拟器会先关闭，未保存的手动进度应自行保存。其他游戏实例不在关闭范围内。

继续某个已保存回合：

```powershell
python tools/run_battle.py --state stage1_v2_t7 --speed 200
```

`t7` 表示第 7 回合结束后、下一回合已经开始的状态。旧实验也使用这些名称，时间较旧的文件不一定属于最新一局；以修改时间和日志为准。

## 本次修复

接手时已有 `Play-Stage1.cmd`、部署脚本、移动范围计算、原生占领函数和自动战术循环。本次修复重点是让这条现有流程连续运行：

| 问题 | 修复 |
|---|---|
| 把 TSV 的 `move=2` 当成坦克移动力 | 它是移动类别；移动预算改用 ROM 条目 `+0x0D`，M1A2 实际为 6，再限制燃料和地形耗费 |
| 用武器攻击力与 HP 直接比较 | 改用攻击/防御比、现存兵数、天气和地形估计扣血；每次攻击后重新读真实 HP、弹药与存活状态再选择目标 |
| 火力分散、己方首都空置 | 优先收掉残血和近处威胁；U0 驻守我方首都，其他部队推进 |
| 最后一击后攻击函数不返回 | 在原生战斗调用尚未返回且敌军已全灭时发送 A，处理游戏自己的投降弹窗；普通交战不触发这段确认 |
| `ENDTURN` 返回值与调用者不匹配 | 统一为成功标志与消息，并检查真的进入下一回合玩家阶段 |
| 把进入结算态就当作胜利 | 必须同时确认 `state=8` 和 `ctx+0x2C=2`，失败结算不会报告成功 |
| 读到上次遗留的 READY | 启动前清理实验握手文件，等待新实例的 `seq=0` 和 READY |
| 回合存档含实验调用桥 | 保存前卸载桥，恢复入口与借用内存，使存档可重新载入 |
| 旧 `run_battle.py` 会关闭胜利窗口、全局杀模拟器 | 统一使用 `play_stage1.py` 驱动，只关闭本项目实例，最终保留窗口 |
| 中文日志显示与错误码不稳定 | `.cmd` 使用 UTF-8、即时输出，暂停后保留实际退出码 |

战斗中的状态和截图持续写入 `shots/native_attack/state.txt`、`current.png`，不再只在整局完成后更新。每次攻击后的详细结果写日志，启动程序每 2 秒显示增量战报。

## 实测证据与产物

首次修复验证在第 8 回合处理原生投降确认并胜利，我方剩 16 单位。随后运行 `python -u tools/play_stage1.py --speed 400`，从部署开始完整复跑：20 单位部署 → 连续战斗 → 最后一击 → 自动接受投降 → **第 7 回合「大勝利」**，我方 16、敌方 0，奖励和累计得分均为 **1706 P**，驱动退出码 0。不同输入时序和随机结算可能影响回合数，不保证每局固定 7 回合。

另外独立读回 `ctx+0x2C = 02`，确认原入口字节恢复为 `30 B5 E9 F7 79 FC 00 06`，借用区起始恢复为零。最终存档和截图已推进到清晰显示「大勝利」及奖励的结算页。控制器正常结束时会等待这段演出完成。

| 文件 | 用途 |
|---|---|
| `states/stage1_v2_victory.State` | 最近一次成功结算存档 |
| `shots/stage1_v2_victory.png` | 最近胜利画面 |
| `logs/stage1_battle_report.txt` | 最近成功对局的攻击与回合报告 |
| `logs/stage1_full_verified.txt` | 完整部署至第 7 回合成功的验证日志，含补丁恢复读回 |
| `logs/native_attack.txt` | 本次运行原生函数、SP、战斗和结算日志 |

| `states/stage1_verified_recovered.State` | 首次验证成功的独立备份 |
| `shots/stage1_victory_recovered.png` | 上述恢复验证的画面 |

窗口由用户双击 `.cmd` 时位于用户桌面；agent 通过沙盒运行时需使用获准的正常桌面 GUI 启动路径。仅设置 `WindowStyle Normal` 无法把窗口从沙盒桌面迁到用户桌面。

ROM MD5 保持 `5FCA8D21555AE60F78F2A44461F2211C`。

## 验证范围

这是代理编写的确定性战术控制器。军表和移动使用内存辅助；移动预算读取原生速度并受地形耗费、格占用和燃料限制。攻击、反击、扣弹、敌方行动、占领与胜负由原游戏执行。没有运行本地语言模型，也没有直接把敌军 HP 写成零或修改胜利标志。

伤害估计用于选择目标，不能保证精确预测每次随机结算。当前军表和战术主要验证第一关，不应据此假定空海军、运输乘客、战争迷雾等规则已完全覆盖。
