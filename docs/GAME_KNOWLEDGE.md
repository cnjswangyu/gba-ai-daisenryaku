## 1. 输入系统

| 项 | 值 |
|---|---|
| KEYINPUT 寄存器 | `0x04000130`（反相：按下位=1） |
| 读键函数 | `0x080015D4`（Thumb），全 ROM 只有 2 处引用 `0x04000130` |
| 输入状态结构 | 指针 `0x02007060` → `0x03000480` |
| `+0x0C` (u16) | 本帧**新按下** |
| `+0x0E` (u16) | **持续按住**（`(held\|new) & pressed`） |

反编译结果（Ghidra，`logs/keyfuncs.c`）：

```c
void FUN_080015d4(void) {
  uVar2 = 0x3FF ^ *KEYINPUT;                  // 反相
  iVar3 = *DAT_080015fc;                      // 状态结构指针
  uVar1 = (*(u16*)(iVar3+0xe) | *(u16*)(iVar3+0xc)) & uVar2;
  *(u16*)(iVar3+0xe) = uVar1;                 // 持续按住
  *(u16*)(iVar3+0xc) = uVar2 ^ uVar1;         // 本帧新按下
}
```

键位：`A=0x1 B=0x2 Select=0x4 Start=0x8 Right=0x10 Left=0x20 Up=0x40 Down=0x80 R=0x100 L=0x200`

### 1.1 按键注入（推荐做法，比 joypad 快 10 倍且不会漏帧）

游戏把读键代码复制到 IWRAM 执行，运行期 IWRAM 有 **5 处** `0x04000130` 字面量：

```
0x03007560  0x0300758C  0x030075A8  0x030075B8  0x03007F94
```

把这 5 处 + ROM 字面量 `0x080015F4` 全改成 **RAM 邮箱 `0x03007F00`**，之后：

```lua
memory.write_u16_le(0x03007F00, 0x3FF - bits)  -- 按下
memory.write_u16_le(0x03007F00, 0x3FF)         -- 松开
```

- ROM 在 BizHawk 里**可写**（`memory.write_*` 到 0x08xxxxxx 生效）
- 邮箱按住 **5 帧 = 光标走 1 格**（1~3 帧不动）
- 实测：一回合 10 个单位下令 **29 秒 / 10 战 10 胜**（打补丁前是 1/10 且常卡死）

## 2. 战场运行时内存

| 地址 | 类型 | 含义 |
|---|---|---|
| `0x030067FC` | u16 | 光标像素 X |
| `0x030067FE` | u8 | 光标六角 **X** |
| `0x030067FF` | u8 | 光标六角 **Y** |
| `0x03002BE2` | 数组 | **我方单位表**，步长 **24** 字节 |
| `0x030010DD`~ | 数组 | **移动范围掩码**：`0xF1`=不可走，其它=可走（选中移动时写入，取消后复原） |
| `0x03000490` | u8 | 移动已提交/待确认标志（1=有未结指令） |
| `0x03006803`~`0x03006806` | u8 | 单位行动相关标志 |

单位运行时记录（24 字节，`0x03002BE2 + i*24`）：

```
+0 x(u8)  +1 y(u8)  +2 hp(u8)  +3 0  +4 ?  +5 0  +6 兵种ID  +7 ?
兵种ID 与 ROM 表 +6 相同：0x05=坦克 0x06=自行炮 0x04=轻步兵 0x28=补给车
```

### 3.1 兵种表（248 条，含重复国家版本）

## 5. 已知坑（务必记住）

1. **`joypad.set` 只对当前一帧有效** → 要按住必须每帧 set；菜单只认边沿所以"菜单能用、光标不动"
2. **1 帧短按会被 vblank 吞** → 关键按键至少 5 帧
3. **移动确认后按 A（待機），绝不能按 B** → B 会**撤销**刚下的移动（表现为单位来回跳）
4. 载入存档后常有横幅/对话框**吃方向键** → 先连按 A 清到"光标能动"为止
5. `dofile` 在 BizHawk 沙箱不可用 → 脚本要自包含
6. `rea` 打不开裸 `.gba`；Ghidra headless 的**项目目录必须先 mkdir**，否则卡在 "Press any key"

## 6. 地形数据（已定位名字表，属性表待攻）

**地形名表**：字符串 `0x08047184` 起（Shift-JIS），指针数组 `0x08761664`，**20 个条目，每条 4 字节**，
按地形 ID 顺序排列：

```
idx 0 0x08047184 (?)
    1 平地   2 荒地   3 丘陵   4 森林   5 山地   6 山岳   7 砂漠
    8 湿地   9 砂浜  10 (?)   11 (?)   12 海    13 (?)   14 橋
   15 工事  16 首都  17 (?)   18 (?)   19 港   …  駐屯地
```

代码引用这三处，是绘制地形面板/资料的地方：`0x0800C084`、`0x0801B644`、`0x0802537C`。

**紧随其后的数据**（`0x087616B8` 起）：

```
+0x00..0x13 : 0,1,2,...,19            ← 地形 ID 枚举（20 个）
+0x14..     : 大量 1~14 的重复值     ← 疑似"移动消耗表"（14 可能 = 不可通行），
                                       按移动种别 × 地形 ID 排布
+0x100..    : 指向 0x0804xx 的指针块 ← 疑似地形图块/图像指针
```

**重要修正（实测）**：状态条上的 `防+30` **不是地形防御**，而是**单位自身的防御值**——
把光标移到没有单位的格子上（27,30 山岳），状态条只显示 `山岳 [29,30]`，`首都/资金/防+` 全部消失。
所以拿"改地形表 → 看 防+ 变化"这条路验证是无效的（已试 0x087616B8~0x08761708 共 80 字节，
全部不影响显示，唯一的 108px 差异是 HUD 动画噪声）。

**还没拿下**：
- 地形对战斗的加成字段在哪（可能需要从伤害公式反推）
- 移动消耗表的确切维度与取值
- 地图数组本体（EWRAM 8 位布局未命中，可能是 16 位）

**下一步思路**：
1. 反编译 `0x0800C084` / `0x0801B644` / `0x0802537C` 三个引用点，看它怎么索引地形属性；
2. 用伤害数值反推：同一兵种对不同地形上的同一目标攻击，伤害差 = 地形加成；
3. 地图数组可以用"光标坐标 → 地形名"的采样来验证（已知每条地形名，可做 60x60 的实地采样建表）。

## 6.5 文字渲染系统（反编译确认，`logs/terrfuncs.c`）

上一轮找的三个"地形名引用点"其实都在**文字渲染**里，不是属性表：

| 函数 | 作用 |
|---|---|
| `FUN_0801b058` | 画一个字：字形位图基址 `0x0801b180`，**每字形 22 字节（0x16）** |
| `FUN_0801b228` | 由字符码查字形：`(code - 0x20) * 2 + 0x08761850` → Shift-JIS 码，再算字形偏移 |
| `FUN_0800140c` | 返回显示页基址 `0x06000000 + page * 0xA000` |
| `FUN_08030904` / `FUN_080308bc` | 按 `param * 100`（ushort）索引，50 项一张表 |

字形定位公式（还原）：

```
glyph_index = (SJIS高字节 - 0x81/0x83/0x84/0xE0) * 0xBC + (SJIS低字节 - 0x40/0x41)
glyph_addr  = 0x0801b180 + glyph_index * 0x16
```

**这条发现的价值**：所有界面文字都走这套渲染 + `0x08761850` 的字符映射表。
顺着它可以把"屏幕上画了什么字"从图块还原成文本——那样 bot 就能**直接读菜单项**
（移動/解散/攻擊/待機）和地形名，不用再靠视觉模型猜，菜单选择也就不会点错。

## 6.6 输入处理函数反编译（`FUN_0800cd20`，`logs/inputfuncs.c`）

这是地图界面的**主输入处理**，解出了三件对 bot 直接有用的事。

### 6.6.1 方向键重复机制（为什么要"按住"才连续走）

```
uVar13 = ~mask & *(u16*)(ctx + 0xC)   // 本帧新按下
uVar8  = *(u16*)(ctx + 0xE) & ~mask   // 持续按住
```

- 新按下 → 立刻执行 1 次移动
- 按住期间计数器 +1：**计数到 4** 再执行 1 次；**计数 > 10** 起每帧执行（连发，`bVar3 = true`）
- 松开则计数器清零

所以精确走 N 格的节奏是：`按下 1 帧 = 1 格`；要走多格就按住到 4、11 之后逐帧。

### 6.6.2 四个方向的移动函数

| 方向 | 位 | 函数 |
|---|---|---|
| 上 | 0x40 | `FUN_0800c694` |
| 下 | 0x80 | `FUN_0800c3a4` |
| 左 | 0x20 | `FUN_0800cb50` |
| 右 | 0x10 | `FUN_0800c984` |

`L`(0x200) = 在单位表里循环找下一个"有指令"的单位（`i*0x18`，跳过 flag&0x81 的），
会直接把光标跳到该单位——**这是"选下一个单位"的正规入口**，比按坐标导航可靠。
`R`(0x100) = 看光标所在格的单位资料（前提是那格 `*ptr == 0` 不成立）。

### 6.6.3 地图格数组（运兵占用表）

代码：`*(byte*)(ctx + x*4 + y*0xC0 + 0x3F60)`

- `ctx = *0x02007060 = 0x03000480`
- 所以数组基址 = **0x030043E0**，**每格 4 字节**，每行 **0xC0/4 = 48 格**
- 实测：格子 `[21,30]` 的值是 `1,1,0,0`，单位站的地方为 1，空地全 0
  → 这是**占用/通行标志网格**，bot 判断"这格有没有人/能不能站"可以直接读，不用试

### 6.6.4 单位表（代码里用的基址）

`*(byte*)(type*0x5c + 0x08798A98 + 0xD)` → **ROM 表基址 `0x08798A98`、步长 0x5C、速度在 +0xD**，
与我们 3.1 节从数据侧推出的布局完全一致（+0x20..24 攻击、+0x25 燃料、+0x26 価格）。

> 待厘清：运行时单位记录里 +6/+7 到底哪个是 type 索引。用 `0x08798A98 + type*0x5C`
> 代入 04/05/06 得到的是飞机（速度 13~14、対海 99），与"坦克/炮兵/步兵"不符，
> 说明该基址指向的表段或索引方式还有一层偏移没对上。

## 6.7 伤害公式与地形加成（反编译 `FUN_0802008c`，`logs/damage.c`）

这是**战斗结算的核心**，全部还原出来了：

```
type_rec = type * 0x5C + 0x08798A98           // 兵种表记录
atk      = type_rec[+0x14 + 目标类别]          // 目标类别 0..4 = 空/裝/人/陸/海
terr     = FUN_08002a5c(x, y)                 // 地形加成（type_rec[+4] != 0 才算）
r1       = floor(atk * unit[+5] / 2550)       // 2550 = 0x9F6
rank     = (type_rec[+0xF] == 1) ? type_rec[+0xE] : FUN_0801ef5c(unit)
dmg      = rank * (atk + terr + r1)
if (dmg > 999) dmg = 999                      // 0x3E7 上限
```

**地形加成的取法**（`FUN_08002a5c`）：

```c
cell = *(byte*)(mapBase + x*4 + y*0xC0);   // 地图格第 0 字节 = 地形 ID
if (FUN_080026d8(cell) == 0) {
    t = FUN_080026cc(cell);
    if (t == 0xF) { /* 建物：走耐久分支 */ }
    return 表A[t];                          // 0x080470B5
} else {
    return 表B[cell - 0x10];                // 0x080470C5
}
```

**表B（普通地形防御加成，按 `cell - 0x10` 索引）**：

| cell | 加成 | cell | 加成 |
|---|---|---|---|
| 0x10 | **30** | 0x23 | 200 |
| 0x11 | 20 | 0x24 | 200 |
| 0x12 | 20 | 0x25 | **250** |
| 0x13 | 20 | 0x26 | 200 |
| 0x14 | 10 | 0x27~0x29 | 200 |
| 0x15~0x22 | 0 | 其它 | 0 |

> 200/250 那一段不是加成，是**建物耐久**（代码里 `t == 0xF` 走单独分支）。

**表A（按地形分类索引，`0x080470B5`）**：`[0,0,0,0,10,10,0,...,0, 5, 30,20,20,20,10, 0...]`

### 这套公式怎么用来"不打以卵击石"

1. 读我方单位 type → `type*0x5C+0x08798A98` 拿攻击 5 列
2. 读目标 type → 同样拿它的攻击列（反击用）与其所在格地形加成
3. 正反各算一次 `dmg`：**我方伤害 < 敌方反击伤害 就不打**

### 已落地：`tools/damage_calc.py`

```
python tools/damage_calc.py                          # 演示
python tools/damage_calc.py --list                   # 列出兵种
python tools/damage_calc.py --atk 74式 --def 軽歩兵 --class 1 --terr 20
```

实测输出（无地形加成）：

```
74式 vs 軽歩兵  类别裝: 我 20 / 它 5   ✔可打
74式 vs FH70   类别裝: 我 20 / 它 5   ✔可打
```

**表索引对上了**：`74式 MBT` 在 `0x08798A98 + 200*0x5C`（index **200**），
名字指针在记录 **+0x00**，攻击列 +0x14~18，燃料 +0x25，価格 +0x26。

> 注意：地图单位记录（`0x03002BE2`）的 +6（我们之前当 type 用的 4/5/6/0x28）
> **不是** 这个表的索引（索引是 200 这种大数）。真正的 type 索引在"战斗单位结构"里
> （反编译里 `*param_1` 是 u16 索引、`*(int*)(param_1+6)` 是指向兵种记录的指针）。
> 地图记录 +6 更像兵种类别/图标号。这一层尚未完全打通。

## 6.9 资金 / 机动力 / 行动状态（实测定位）

### 6.9.1 势力表（含资金与首都坐标）

`0x030004A0` 起，每条 **12 字节**，实测两条（我方/敌方）：

| 地址 | 内容 | 实测值 |
|---|---|---|
| +0x00 | 资金 (u32) | **1500**（我方）、1500（敌方，与剧本"敌军资金1500"一致） |
| +0x04 | id1 / id2 / ? / **x** | `1 2 16 21` → x=21 |
| +0x08 | **y** (u32) | 30 |

- 我方：资金 `0x030004A4 = 1500`，首都 **(21,30)**
- 敌方：资金 `0x030004B0 = 1500`，首都 **(32,27)**
- `0x030004E4 = 2` → 参战势力数
- `0x030004E8 = 2500` → 疑似资金上限/预算

> 状态条上那个 `首都 1250/250` 与这里的 1500 不同，应另有含义（待确认）。

### 6.9.2 单位记录字段修正（重要！）

移动 2 格前后对比（`0x03002BE2 + i*24`）：

```
移动前 u0: 21 30 45 0 8 0 5 5
移动后 u0: 23 30 43 0 8 1 5 5
```

| 偏移 | 含义 | 证据 |
|---|---|---|
| +0 | x | 21 → 23 |
| +1 | y | 不变 |
| **+2** | **燃料（不是 HP！）** | 45 → 43，**每走 1 格扣 1**；74式 ROM 燃料正是 45 |
| +3 | 0 | |
| +4 | ? （坦克 8 / 自行炮 4 / 步兵 24 / 补给 4） | 待定 |
| **+5** | **本回合已行动标志** | 0 → 1 |
| +6 | 兵种类别/图标号（坦克 5、自行炮 6、步兵 4、补给 0x28） | 注意**不是**兵种表索引 |
| +7 | ? | |

**"还能走多远"的判定**：
1. `+5 == 1` → 本回合已经动过，不能再动
2. 否则每回合可走格数 = 兵种 `速度`（我方全是 5）
3. 真正的可达格集合 = 选中「移動」后读**范围掩码** `0x030010DD`（`0xF1` 不可走，其它可走）
4. 长期续航看 `+2` 燃料，每格 -1，归零就动不了（需要补给车）
