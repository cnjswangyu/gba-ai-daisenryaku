> 逆向实证文档，写于 2026-10-18。所有结论均有「Ghidra 反编译 × BizHawk 快照实测」双重证据。

## 1. 启动链（冷启动 → 主循环）

```
BIOS → crt0(0x080000C0) → main(0x08000229, Thumb)
                              │
                    ┌─────────┴──────────┐
                    │ main 初始化段       │
                    │ *(0x02007060) =    │  ★ 全局上下文指针槽
                    │   0x03000480       │
                    └─────────┬──────────┘
                              ↓
        主循环头 0x08000392（每帧）:
          bl FUN_080006AC   ← 每帧引擎（自旋等 VBLANK、进度条、声音序列）
          bl FUN_080015D4   ← 按键边沿计算（写 ctx+0x0C/0x0E）
          ldrb r0,[ctx]     ← 取 state
          cmp r0,#0xE / lsl r0,#2 / ldr r0,[r0,r1] / mov pc,r0   ★ 跳转表分派
```

- 跳转表 @`0x08000480`，15 项，每项指向 dispatcher 区内的小 thunk（如 state6 → `0x080004E4`）
- thunk 实体：`movs r0,#0; movs r1,#0; bl <handler>; b <公共尾>` —— **handler 收两个参数，阻塞式运行整个界面**
- 公共尾 `0x0800051C`：非法 state 时递增 ctx+8 后回循环

### ctx 大状态块（`0x03000480`，IWRAM，实际跨度 25KB+）

| 偏移 | 地址 | 类型 | 含义（实测） |
|---|---|---|---|
| +0x00 | 0x03000480 | u8 | **主状态** state（0–14） |
| +0x01 | 0x03000481 | u8 | **子步骤** substep（向导内步骤 / 界面阶段） |
| +0x08 | 0x03000488 | u32 | 子状态计数器（公共尾每帧 +1；编成表=0xB、转场=0x17、战场=0xB6） |
| +0x0C | 0x0300048C | u16 | 本帧**新按键**（主动高，A=1/B=2/START=8/方向=0x40/0x80…） |
| +0x0E | 0x0300048E | u16 | **持续按住** |
| +0x14 | 0x03000494 | ptr | **剧本数据指针**（军事演习1 = `0x08762B10`） |
| +0x68 | 0x030004E8 | u32 | **资金**（初始 1500，上限 1000 万） |
| +0x188 | 0x03000608 | u16×99 | **部署单位槽**（ID + 状态；状态 bit8=0x0100 已部署） |
| +0x990 | 0x03000E10 | u8 | 当前玩家/选中索引 |
| +0x637C | 0x030067FC | u16 | 战场光标像素 X |
| +0x637E | 0x030067FE | u8 | 战场光标六角 X |
| +0x637F | 0x030067FF | u8 | 战场光标六角 Y |
| +0x2762 | 0x03002BE2 | — | **战场我方单位表**（步长 24：+0 x, +1 y, +2 hp, +4 机动力, +6 类别码） |

> 关键认知：ctx 不是小结构，而是从 `0x03000480` 连续延伸到 `0x03006810`（帧计数器）的**统一游戏状态块**——界面字段在低地址，战场运行时字段在高地址。

## 3. 剧本表（state3 选择 → state4 详情）

**剧本表 @ `0x08761174`**：指针数组，每项 8 字节 = `[剧本名/数据 ptr][地图瓦片数据 ptr]`，最多 48 项，空项终止：

| # | 剧本数据 | 名字 | 地图数据 |
|---|---|---|---|
| 0 | `0x08762B10` | **軍事演習１**（目标剧本） | `0x08762C30` |
| 1 | `0x08763E8C` | 軍事演習２ | `0x08763FAC` |
| 2 | `0x087652BC` | 軍事演習３ | `0x087653DC` |
| … | … | （共 20+ 个：第三次嘗試、漁夫之利、狭窄島的反抗…） | … |

**剧本数据结构**（以軍事演習１ @`0x08762B10` 为例）：

```
+0x00  16B  剧本名 shift_jis（"軍事演習１"）
+0x10  参战方数据，每方 0x18 字节：
        +0x00  8B  阵营名（"BLUE"/"RED"）
        +0x08  u32 旗号(0x1401)
        +0x0C  u32 资金 ← state4 公式读这里：*(剧本+0x24+玩家idx*0x18)
```

state3 筛选条件（反编译）：`剧本+0x70 <= 玩家+0x65` 且 `剧本+0x7b == 7 或 == 玩家+0x64`。

### state4 详情页装载逻辑（`FUN_08007364` 反编译）

```c
// 首次进入（substep==0）：
FUN_0804024c(0x02000018, ctx+0x188, 0x18C);   // ★ Commander 数据(姓名+99单位ID) → ctx 部署槽
地图预览 = ROM 0x081C6CD0 / 0x081C2740（DMA3 @ 0x040000D4）
资金 = ctx+0x68 + *(剧本数据 + 0x24 + 玩家idx*0x18);   // 1500
if (资金 > 0x0098967F) 资金 = 0x0098967F;              // 上限 1000 万
// 交互：↑↓ 移动光标（0x80/0x40），B 回 state3，A 确认 →
if (光标==0) { *ctx = 6; ctx[1] = 0; }    // ★ 开始 → state6 出击编成表
else        { *ctx = 5; ... }              // 第二项 → state5 战术地图
```

## 4. 单位数据库（ROM `0x08798A98` 起，stride 0x5C）

**条目地址 = `0x08798A98 + (ID-1) × 0x5C`**（ID 从 1 开始，0 = 空槽；201+ 条目，末端 `0x0879D2D4` 起衔接可变长详情表）。

```
+0x00  4B   单位名字 ptr（→ 0x08067400+ 文本区，shift_jis）
+0x04  24B  属性区（12×u16）：
           +0x06  u16 低字节 = ★兵种类别码（FUN_08002c9c 用它分类）
           +0x08  u16 机动力相关
           +0x14  u16×2 装甲/机动之类
+0x18  64B  4 组武器槽，每组 16B（数据4B + 名ptr4B + 弹药等8B），未用填 0
```

**分类函数 `FUN_08002c9c`**（按 ROM 表 +0x06）：
- `< 8` → 类别 2（机械化：坦克/火炮/补给）
- `8–18` → 类别 1
- `≥ 19` → 类别 3（空军）

**"军事演习1"默认编成实证**（s72/s73 快照 ctx+0x188 + ROM 表互证）：

| slot | ID | 数量 | 单位 | 武器 | 类别码 |
|---|---|---|---|---|---|
| 0–2 | 0xC8 | ×3 | 豹2A6 | 120mm 滑腔 + 机枪 | 3 |
| 3–4 | 0xEF | ×2 | FH155-1 | 155mm 榴弾 | 5 |
| 5–8 | 0x131 | ×4 | 軽歩兵 | 步枪 + 反坦克弹 + 肩扛 SAM | 0 |
| 9 | 0x158 | ×1 | 補給車 | 補給物資 | 7 |

## 5. 出击编成表 + 战场（state6 `FUN_080099B8`，1998B）

### 5.1 每帧流程（param_1=0，主循环 thunk 调用）

```
FUN_080099B8(0, 0)
 ├─ 首帧初始化：清 ctx 光标/阶段字段，FUN_08003480()
 ├─ FUN_08009348：扫 99 个部署槽(ctx+0x188) → 按 FUN_08002c9c 分类
 │                → 300B 清单（3 段 ×99：类1 @0、类2 @99、类3 @198，条目存 slot+1，bit7=标志）
 ├─ OP 过场动画：20+12+20 步卷轴（图形 ROM 0x08093500，DMA3）
 ├─ FUN_08009554：渲染单位行 ← (id-1)*0x5C+0x08798A98 取名字/类别/数量(ctx+0x18A)
 ├─ FUN_08009854（有单位）/ FUN_080098f4（无单位）：画按钮
 └─ 交互循环：等 A（开始）→ sub 0xB→0x17→0xB6 进入战场
```

### 5.2 战场装载（sub=0xB6）

- 部署槽 ID ×0x5C → ROM 单位表 → **RAM 我方单位表 `0x03002BE2`**（步长 24）
- 进入战场时 slot 状态位 `0x0000 → 0x0100`（"已部署"标记，s94/s95 实测）
- RAM 单位 +6 = ROM 表 +0x06（类别码，s95 单位 0 的 0x05 = FH155-1 ✓）
- 地图瓦片数据：`ctx+0x1C = 0x08762C30`（大片 0x0C0C 地形码）
- param_1=2 分支：state5 调 `FUN_080099B8(2, idx-1)` 查看/配置单个单位

### 5.3 state6 字面量池速查（反编译符号 → 真实地址）

| 反编译符号 | 值 | 含义 |
|---|---|---|
| `_DAT_08009b58` | 0x02007060 | ctx 指针槽 |
| `_DAT_08009b7c` | 0x08798A98 | **单位表基址** |
| `_DAT_08009c60` | 0x08093500 | 出击编成图形区 |
| `_DAT_08009c58` | 0x040000D4 | DMA3SAD |
| `_DAT_08009c54` | 0x0200504C | 一次性初始化标志（state4 共用） |
| `_DAT_080093a0` | 0x08798A98 | 清单生成表基址 |
| `_DAT_08009600` | 0x08798AF4 | 渲染表基址（= 0x08798A98+0x5C，配合 (id-1) 等价） |

## 6. 对 Bot 自动化的重要意义

1. **买兵/编成 = 写 ctx+0x188**：99 个 u16 ID 槽 + u16 状态。改 ID 即换兵种（单位表 `0x08798A98+(ID-1)*0x5C` 查属性），无需点 UI。
2. **资金 = ctx+0x68**（0x030004E8），上限 1000 万（0x0098967F）。
3. **战场状态全在 ctx 高地址**：光标 0x030067FE/FF、单位表 0x03002BE2、帧计数器 0x03006810。
4. **界面切换 = 写 ctx+0x00**：`*ctx = 6` 直接进出击编成表（state4 A 键就是这么做的），可跳过中间 UI。
5. **存档点复用**：`states/battle_start.State`（刚上战场）+ `states/pre_battle.State`（出击编成）配合本文结构读写。
