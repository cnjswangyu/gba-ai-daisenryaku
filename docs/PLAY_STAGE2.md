# 第二关一键程序

双击项目根目录 **`Play-Stage2.cmd`**。程序会载入已保存的「军事演习 2」出击前现场，保留 16 个老兵，补齐 4 个空槽，通过游戏清单自动部署，然后在可见 BizHawk 窗口连续战斗，处理投降/胜利确认，最后保留结算页。

```powershell
.\Play-Stage2.cmd
.\Play-Stage2.cmd --speed 100
.\Play-Stage2.cmd --speed 400
```

默认 200% 速度、简化战斗演出。100% 便于观看，400% 适合较快验证。程序使用现有 Python 与 BizHawk，无需额外安装。

## 续打与恢复

默认每次从第二关出击前的固定备份开始，购买只作用于本次载入的战局，重复运行不会在上次结果上叠加扣款。

```powershell
# 跳过部署，从本次配置的第一回合重新打
.\Play-Stage2.cmd --fast

# 从第 5 回合结束后保存的下一回合继续
.\Play-Stage2.cmd --fast --state stage2_t5 --speed 200
```

回合存档可能来自不同时次的实验，以文件修改时间为准。运行会关闭本项目已有模拟器，需保留的手动进度应先保存。使用 `--timeout 1800` 可指定战斗等待上限，超时或失败时窗口保留供检查。

## 兵力和经验

继承军表：M1A2×8、M-109A6×3、轻步兵×2、空降兵×2、补给车×1。追加 M1A2×1、M-109A6×2、补给车×1，总计 20 单位。

新增单位按 ROM 价格扣款，共 **205**：4193→3988。仅填充空军表槽，不重置老兵的 ID 或 EXP。部署完成后，程序根据原生部署关联把 16 个老兵逐个对应到战场记录，确认经验与出击前完全相同；核验日志为 `logs/stage2_deploy.txt` 中的 `EXP_OK`。

这里补兵通过已确认的军表字段追加并扣款，清单勾选、部署和开始战斗通过游戏输入执行。移动受原生速度、地形耗费、占用格和燃料约束，由内存辅助落格；攻击、反击、弹药、敌方行动和胜负由原游戏处理。程序不直接把敌军 HP 写零，也不修改胜利或经验值来获胜。

## 第二关策略

- U0 守住我方首都，其他部队推进。
- 使用逆向地形耗费的反向距离场引导推进，绕过中央不可通行山地；每回合只移动到当前预算允许的位置。
- 接敌后按实际伤害读回选择目标，优先处理炮兵、反坦克车和可击杀目标。
- 攻击落点评分允许零防御平地，避免因为初始分数过高而漏掉本可执行的攻击。
- 首都空置且占领兵可达时调用原生占领，否则继续清场；最后一击在原生调用尚未返回时处理投降弹窗。
- 成功必须同时确认 `state=8`、`ctx+0x2C=2`，随后等待胜利演出并保存结算画面。

新增补给车已编入军表，但当前控制器尚未主动调用完整的运输/补给菜单动作，不能把它理解为已实现完整后勤 AI。

## 文件与数据隔离

| 文件 | 用途 |
|---|---|
| `tools/play_stage2.py` | 第二关入口，复用共同的启动、窗口与握手驱动 |
| `lua/deploy_stage2.lua` | 保留老兵、补兵扣款、原生部署、经验核验 |
| `tools/native_attack.py --build --stage 2` | 生成第二关配置的战斗桥，开启绕山寻路 |
| `states/stage2_pre_battle.State` | 固定的出击前输入备份 |
| `states/stage2_before_program.State` | 接手时的现场备份 |
| `states/stage2_army_ready.State` | 补兵后、勾选部署前 |
| `states/stage2_deployed.State` | 20 单位已出击，第一回合待命 |
| `states/stage2_t*.State` | 各回合结束后的恢复点，保存前卸载调用桥 |
| `states/stage2_victory.State` | 最近成功结算 |
| `shots/stage2_victory.png` | 胜利结算截图 |
| `logs/stage2_deploy.txt` | 补兵与经验保留证据 |
| `logs/stage2_native_attack.txt` | 原生战斗、移动调度及调用栈校验 |
| `logs/stage2_battle_report.txt` | 最近成功对局摘要 |
| `logs/stage2_window.json` | 可见桌面核验，正常应为 Default |

命令握手仍复用 `shots/native_attack/`，因此同一时刻只运行一个项目控制实例。第二关回合、胜利存档、截图和战报均使用 `stage2` 前缀，不覆盖第一关胜利记录。

最终已运行 `python -u tools/play_stage2.py --speed 400`，从出击前现场完整复跑成功：**第 6 回合「大勝利」；我方 19、敌军 0，获得 1836 P，退出码 0**。军表槽 8 的 M-109A6 从继承的 28 经验自然升到 **33 / D 级**。原生胜利字节独立读回为 `02`，入口恢复为 `30 B5 E9 F7 79 FC 00 06`，借用内存起始恢复为零。

第一轮也已通关（第 15 回合、剩 10 单位、1543 P），但围城效率较低。原因是 `best_reach_cell` 的初始最佳分数为 -1，而平地候选会因移耗扣分成为负数，导致可用落点被漏掉；改为 -1e9 后正常参与比较。该轮备份在 `states/stage2_first_verified_victory.State`、`logs/stage2_first_verified.txt`。最终证据在 `logs/stage2_full_verified.txt`。

这些是实际跑出的结果，随机结算、输入时序和存档起点变化可能改变回合数，不保证每次都恰好 6 回合。第一关胜利存档及截图的 SHA256 在第二关运行前后保持一致。
