## 一、军表与出击的内存结构（全部实证）

### 1. 部署池（军表本体）

- 池 = `ctx+0x188`（`0x03000608`），99 槽 × 4 字节：
  - `+0/+1` u16 单位 ID（0=空）
  - `+2` LV（0=E 级）
  - `+3` flag（运行时由游戏写：**部署后 = 部署序号 1..N**；清单勾选态不在池里）
- 资金 = `ctx+0x68` u32。**写池不扣钱**——扣钱只发生在购买界面；脚本配置需手动扣（`memory.write_u32_le(CTX+0x68, money-cost)`）。

### 2. 清单界面与勾选（state6）

- 入口路径：出击编成表 → `B` → `A`（到 state4）→ `A`（入口框）→ `A`（清单）。
- **清单的 A = 勾选/取消**该行单位（右上「剩余」每勾一个 -1）。清单每帧由 `FUN_08009348` 重建：扫 99 槽，按类别分 3 组（class1/2/3），条目 = 1-based 槽号。
- 勾选态真身（排除法结论）：不在池 flag（确认前恒 0）、不在 `ctx+0x10/0x11`（那是"当前行勾选显示态"）、`0x02005034` 是随机数发生器、`0x02005035` 是已勾选计数（勾行0→01，行1→02）。**持久真身 = 确认时由放置函数写进池 flag 的部署序号**。
- 首行第一次 A 会被吞（清单刚打开时），需先垫一次。

### 3. 确认框与配置阶段

- `START` → 「自動部署至地圖被選定的單位？」：**A=出撃（部署勾选集）/ B=取消（Ghidra：写 `*ctx=1,ctx+1=1` 回军备编成）**。零勾选确认≈空部署。
- 确认 A 的执行块 = `FUN_08000b20`（=`FUN_0800099c(0x35,0x36,...)` 动画调度）+ `FUN_08001198/0800128c`（逐单位过场，180 帧强制推进）——**纯演出，无游戏逻辑**，可放心跳过。
- 确认后进入**配置阶段**（state=6、光标钉在首都）：不是卡死。再 `START` → 总菜单第一项「开始战斗」→ `A` → 清「演習标题/第1ターン」横幅 → state=7 sub=1 ph=3 side=0 才是真战斗。
- 状态直跳实验：写 `ctx+0=1,ctx+1=1` 确实切状态机，但 state1=军备编成界面（剧本默认军表），不可作出击入口。

### 4. 放置函数 `FUN_08003568(x, y, 池槽号)` —— 出击的本质

```c
id = 池[slot*4];  在战场单位表(ctx+阵营*0x600)找第一个空槽 s (stride 0x18, ≤64);
记录+0/+1 = id (u16);  +2/+3 = x,y;  +4 = db[+0x19](=燃料);
+5 = 池[slot*4+2](LV);  +6 = db[0xF]*db[0xE](=HP);  +7 = 0(状态);
+8..+11 = db[+0x26+i*0x10] (i=0..3, 各武器弹药);
格表[x*4+y*0xC0]   = 阵营+1;
格表[x*4+y*0xC0+1] = s+1;
池[slot*4+3]      += s+1;   // ← "确认后 flag=部署序号"的写入点
```

配套 `FUN_080084e4` = 自动放置位置搜索（从锚点螺旋向外找可用格）。  
**推论**：出击的最终产物（战场单位表+格表）完全可内存复刻——在已部署存档上换兵/加兵不需要再走出击界面（本项目 `lua/rearm.lua` 已实证：直接抄原生放置的 24 字节记录换兵种，30 帧后无回写）。

## 二、武器/射程表（战术的数字基础）

### 单位数据库基址勘误

- **真实基址 = `0x08798AF4`**（HANDOFF 写的 `0x08798A98` 差一个条目位；原生攻击桥的 `id*0x5C` 写法等效于 `0x08798AF4 + (id-1)*0x5C`）。
- 单位条目 0x5C 字节：+0x18 起武器槽 4 组 × 0x10：
  - **槽+0x0D = 最大射程**
  - **槽+0x08+目标类别 = 攻击力**（类别 = 目标条目+4，0=空/1=装甲/2=人员/3=陆/4=海）
  - 槽+0x0E = 该武器对应单位记录弹药的初值来源
- 武器选择 `FUN_08023940(unit_rec, 目标类别, 距离)`：遍历 4 槽，条件 = 记录弹药>0 且 **距离 ≤ 槽+0x0D**，取攻击力最高者。

### 第一关关键兵种数据（本剧本）

| 兵种            | 武器  | 射程    | 对装     | 对人     | 对陆 |
| ------------- | --- | ----- | ------ | ------ | -- |
| M1A2 (187)    | 主炮  | 1     | **70** | 35     | 10 |
| M-109A6 (241) | 榴弹  | **3** | 30     | 45     | 10 |
| T-72B (188)   | 主炮  | 1     | **50** | 35     | 10 |
| 軽歩兵 (305/301) | 步枪  | 1     | 5      | **40** | 0  |
| 軽歩兵           | 火箭筒 | 1     | **45** | 0      | 0  |

伤害修正（`FUN_08030644` + 实测）：天气 1=100%、0/2=85%、3=70%（`ctx+0x23`=天气，表在 ROM `0x087A3944`，本剧本 `3 3 0 1 1 1 2 3`）。

## 三、自动化通关（AUTOCLEAR v2）

`python tools/native_attack.py AUTOCLEAR`（桥内命令，单命令全自动）：

1. **军表 20 单位**：M1A2×9 + M-109A6×4 + 軽歩兵×4 + 空降傘兵×2 + 補給車×1（资金 1059/2500）；
2. **射程表驱动**：每单位对每敌枚举「原地攻/瞬移到 dist=1..3 攻」，评分 = 我方攻击力×10 − 敌方反击攻击力×8 → 炮兵自动拉开距离 2-3 无反击输出，坦克贴脸；
3. **地形优先**：瞬移落点在同距离空格中选防御加成最高（首都+30 > 市街+20 > 森林+10）；
4. 步兵只在敌残血/敌步兵时出手，补给车待机；每回合存档 `stage1_v2_t*.State`。

**战果：第 2 回合全歼敌军 14 单位**（29 次攻击，奖金 +261），记录 `stage1_v2_victory.State`、`shots/stage1_v2_victory.png`。对照：v1 无战术版 11 回合未胜。

## 四、坑与教训

1. **出击态（state6）打邮箱补丁 → EmuHawk 静默崩溃**（两次复现）。邮箱只在战场态打；出击阶段用 joypad（战场光标方向键需 hold 13-14 帧，菜单键 4-6 帧）。
2. **禁沙箱启动的长跑进程会被宿主清理**（数分钟级）；跑长任务要么放沙箱，要么在单回合内完成。
3. FUN_08003568 复刻时注意 `U = 0x03002BE2` 指向记录+2：id 在 `U+k*24-2`，弹药在 `U+k*24-2+8+wa`。
4. `0x02005034` 随机数、`0x02005035` 勾选计数——**会变的字节 ≠ 变量**（第三次踩坑，与 `0x0300756F` 同类）。
