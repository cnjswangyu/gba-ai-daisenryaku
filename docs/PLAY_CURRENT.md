## 可以停在哪里

| 启动时界面 | 行为 |
|---|---|
| 剧本选择 | 按当前高亮项目进入，不擅自改选第一关 |
| 剧本详情、尚未按开始 | 识别实际剧本，进入出击准备 |
| 出击前自动部署提示 | 保留老兵和经验，按对应关卡的已验证方案补兵、扣款、部署 |
| 已有单位部署、尚未开始战斗 | 沿用现有部队数量，走原生出击确认，进入战场 |
| 已开战 | 等待玩家阶段，退出菜单，接着当前进度打到结束 |
| 胜利、晋升、标题等界面 | 停止并提示；不会自行再开一局 |

自动补兵部署仍使用目前的 20 单位方案；已有部队在场时沿用实际数量，不要求正好 20 个，由游戏原生出击确认决定能否开始。部署清单尚未完成，或待补兵军表与方案不符时，可以先手动完成部署进入战场，再运行入口。它不会为了凑方案删除你的部队。

因此重复第一关的用法是：结算后自行重新选择第一关，可以停在详情页、出击前或进入战场后，再双击同一个 CMD。沿用现有档案的累计成绩；每次只打一局。若希望全自动重复直到晋升，另用 `Farm-Stage1.cmd`。

## 可选参数

```powershell
.\Play-Current.cmd --speed 100
.\Play-Current.cmd --speed 400
.\Play-Current.cmd --pid 24860
.\Play-Current.cmd --check
```

默认速度 200%，100 为原速。多个同游戏窗口时用 `--pid` 指定，程序不会猜测。`--check` 只装入控制器并确认就绪，不开始战斗。接管会用 Lua Console 的 New Session 停止旧 Lua 脚本，避免多个脚本同时按键。请不要同时运行旧通关/刷关控制程序；同一新入口的重复双击会被互斥锁阻止。

从正常 Windows 桌面运行 CMD，保持模拟器和 Lua Console 可见。接管菜单时需要几秒钟，请暂时不要操作鼠标键盘。它通过真实窗口菜单加载 Lua，而不是创建后台模拟器。

## native_attack.py 会不会影响后续关卡

它是共享的 Lua 生成器，包含原生函数桥、地图移动、战斗策略及历史关卡参数。修改公共逻辑确实可能影响所有使用它的入口，旧版 `--stage 1/2` 也会重写同一个 `lua/native_attack.lua`。

新入口用 `--build --current` 生成独立的 `lua/current_battle.lua`，不覆盖旧桥脚本；从游戏内存识别当前剧本，关卡准备放在独立文件。第一关使用自身方案，其余关卡默认沿用第二关兵力和地形寻路。新入口的窗口适配、存档命名和回合等待不会改变旧复现入口的运行流程；不是每次玩都要修改 Python。

移动与补兵仍沿用项目已有内存辅助；攻击伤害、经验、胜负、评分入账和军衔晋升均由原游戏计算，不是纯按键 AI。

## 本次验证

`endgame-v5` 针对第三关 30 回合败局继续调整（仅离线验证）：不足四个敌人或三轮无有效进展时，按目标、真实武器最大射程、弹药、路径耗油分配最多三支歼敌单位；移除“攻击落点只考虑1–3格”的限制。无占领兵存活时不再把不能占领的坦克留在敌首都周围假围城。预计可射击的首都驻军也计入解决方案，但仍不离岗。

缺弹也触发恢复需求。恢复路径必须在剩余油量内；已有城市节点时，会考虑回程油量，提前转入补给。占领兵遇到预测火力时，要求附近确有健康、带弹战斗单位支援；护送任务改为跟随步兵当前位置，而不是自己先跑去远方城市。此改动不包含运输上下车或主动补给车菜单，不能保证任意残局都能挽回。

`ENDGAME`/`CLEANUP`/`BLOCKED` 日志显示当前能否执行歼敌方案。三轮无有效战果或恢复进展时保存 `_stalled.State` 和 `shots/current_battle/stalled_map.json`，便于只读分析剩余敌人的实际地图。六轮无进展、找不到带弹且油量可达的射击方案、也没有占领兵时，以 `FAIL NO_CURRENT_PLAN` 停止并保留现场；它表示当前自动策略没有方案，不是证明人工也无法获胜。失败不再显示 `OK FAIL`。下次 CMD 自动构建新版；不热更正在运行的脚本。

2026-10-19，策略更新为 `strategy-v4`（离线验证）：原地射程内预计能消灭的目标优先于驻城、占领和截击任务，避免看着身边残血敌人不打。首都仍保留驻军，额外预备队改为按实际威胁分配：后方安全为 0 支、有威胁为 1 支、敌军集中时为 2 支，不再每轮固定扣留两三辆坦克。前线敌人不因“在首都18格内”就自动触发回防；根据距首都的距离、接近趋势和移动预算判断是否构成近期威胁。

每轮 `STRATEGY` 日志列出敌我数量、归一化剩余兵力、首都附近威胁，以及敌军在首都东南西北的分布。模式在推进（advance）、扩大战果（exploit）、拦截（intercept）、防御（defend）间调整；部队选择进攻目标时考虑敌方主要方向、目标附近敌我数量和敌首都，而不是只追最近敌人。

城市恢复同时看 HP 和燃料：HP 低于75%或油量低于35%时寻求恢复；进入恢复后等待 HP 至少90%、油量至少80%再释放。`RECOVER` 日志记录实际血量/油量变化；三轮无增长的节点不再享有恢复停留加分，会尝试其他城市。不同设施和兵种的恢复能力仍由原游戏决定，不直接增加 HP/燃料，主动补给车菜单仍未实现。以上规则已做近身歼敌、预备队释放、敌军分布/数量和城市加油的离线回归，尚未跑新版完整实战。

任务与轨迹修正（`missions-v3`）：占领兵先分配持续的城市/敌首都任务，优先于临时找敌人攻击；已占城市会重新分配新目标，敌首都被占位时先接近其周边。可用战斗部队会承担护送任务。首都常驻守军外，平时保留两支近邻预备队，受威胁时增加一支；普通坦克优先承担防守，尽量保留步兵用于占领。每轮比较敌方距首都的距离，18 格内或持续向首都靠近且在 24 格内的敌人会进入拦截分配，优先威胁首都的占领兵，最多安排约三成部队，每个威胁最多两支；被分配拦截的单位不会转头追别的敌人。威胁估算现考虑完整敌方移动预算，仍为近似模型。
