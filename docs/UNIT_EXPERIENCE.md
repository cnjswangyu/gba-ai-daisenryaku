# 单位经验值、等级与持久保存

已核对本地 ROM 原生读写函数，并在第二关出击军表和敌军记录中只读验证。经验是 **u8（0..255）**，等级由经验计算，二者不是同一个字段。

## 地址

| 场景 | 经验地址公式 | 槽 0 示例 |
|---|---|---|
| 出击军表 | `0x0300060A + 军表槽号*4` | `0x0300060A` |
| 我方战场单位 | `0x03002BE5 + 战场槽号*24` | `0x03002BE5` |
| 敌方战场单位 | `0x030031E5 + 战场槽号*24` | `0x030031E5` |

统一战场公式为 `record+5`，其中 `record=0x03002BE0+side*0x600+slot*0x18`，side=0 我方、1 敌方。

旧代码的 `U=0x03002BE2` 指向坐标，不是记录开头；相对这个 U，经验位于 **U+3**。行动标志则是 U+5，别把两者混淆。

只读示例：

```lua
local rosterSlot = 8
local exp = memory.read_u8(0x0300060A + rosterSlot * 4)
console.log("Roster EXP: " .. exp)
```

## 等级阈值

| 经验 | 显示等级 |
|---:|---|
| 0–29 | E |
| 30–79 | D |
| 80–149 | C |
| 150–239 | B |
| 240–255 | A |

本 ROM 的最高已证实等级为 A，没有找到 S 级证据。`FUN_0801F03C` 比较 30、80、150、240，返回 4..0；`FUN_0801F014` 用该值查询 ROM `0x08047490` 的 A/B/C/D/E 字符串表。

## 查询命令

```powershell
python tools/native_attack.py XP ROSTER
python tools/native_attack.py XP MY
python tools/native_attack.py XP EN
```

每行打印槽号、兵种 ID、经验、等级与准确地址。`MAPDATA` 导出的 JSON 也包含每个单位/军表槽的经验及地址。本次未修改经验。

第二关当前我方最高为军表槽 8 的 M-109A6：**28 点、E 级，地址 `0x0300062A`**，距 D 级差 2 点。敌方槽 18 反坦克车为 40 点、D 级，地址 `0x03003395`。我方全部 16 个存活单位当前仍为 E，不能据此认为它们没有积累经验。

## 原生读写和战后保留

- `0x0801F060(record,delta)`：增减经验，夹在 0..255；写入指令位于 `0x0801F074`。
- `0x08003568`：部署时把军表槽 +2 复制到战场记录 +5。
- `0x08022BE8`：战斗根据实际结果和双方旧经验计算增加值；不是固定每攻击一次加同样经验。
- `0x08020B20`：占领动作调用原生经验函数加 3。
- `0x080036AC`：战后把存活单位经验写回对应军表，并压紧军表；结果界面在 `0x0800F1EE` 调用它。
- 原生指挥官存档保存 0x2C0 字节档案，军表经验在保存范围内。

军表槽号与战场槽号可能不同，回写依赖真实部署关联。已经出战时应查询战场记录；部署前查军表。原生演出中会暂存旧经验用于动画，最终值要等战斗调用完成后再读。

静态证据和详细方法：`logs/unit_experience_findings.md`、`logs/unit_experience_save.c`、`logs/damage.c`、`logs/deploy_place.c`。REA 连接未提供可用工具，本次沿用本地 Ghidra 只读分析，证据不冒充 REA 输出。
